# Реєстр активів АРМА — демоверсія

Статичний прототип для погодження дизайну і структури. Бекенда немає, дані умовні
(`assets/js/data.js`). Публікується на GitHub Pages або відкривається з диска.

**Починати з `login.html`.**

## Сторінки

| Файл | Призначення |
|---|---|
| `login.html` | Сторінка входу |
| `index.html` | Огляд портфеля: обсяг повноважень, структура, МТУ, відділи ДМА, нерозподілені |
| `realestate.html` | Нерухомість |
| `land.html` | Земельні ділянки: карта, завантаження GeoJSON |
| `transport.html` | Транспорт і техніка |
| `property.html` | Рухоме та інше майно, спільні комплекти фото |
| `corporate.html` | Корпоративні права: пул компаній |
| `company.html` | Картка компанії у форматі YouControl |
| `money.html` | Кошти, банківські метали, ОВДП |
| `crypto.html` | Криптоактиви — за службовою запискою (4 складові) |
| `asset.html` | Картка активу: реквізити, фото, документи, хронологія рішень, план дій |
| `admin/index.html` | Адміністрування: списки з фільтрами, редагування, файли, права |
| `admin/plans.html` | Плани дій (CRM-ланцюг кроків) |
| `admin/reports.html` | Звіти, у т. ч. у розрізі відділів ДМА |

## Принципи, закладені в структуру

1. Аналітика і адміністрування розділені: у категоріях — представлення даних,
   в адмінці — списки з фільтрами для оновлення.
2. Кожна категорія має однакову побудову: показники → діаграми → пошук → список → картка.
3. Адреса вводиться уніфіковано: область, тип населеного пункту, тип вулиці — списками.
4. Пошук і звіти працюють як за МТУ, так і за відділами ДМА.
5. Файли не дублюються: однаковий комплект підключається до кількох активів посиланням.

## Публікація

    git init && git add . && git commit -m "ARMA registry prototype"
    git branch -M main
    git remote add origin https://github.com/<org>/<repo>.git && git push -u origin main

Settings → Pages → Source: `main`, папка `/ (root)`.

## Бібліотеки

Chart.js 4.4.1 з плагіном datalabels, Leaflet 1.9.4, шрифт IBM Plex — з CDN.
Для закритого контуру покласти локально.
